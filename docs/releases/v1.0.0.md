## 发布结论

v1.0.0 已达到“完整第一版、可以日常使用”的标准。上传、服务端高准确节拍分析、首尾残缺小节、人工拍点相位校准、通用播放器手势、单节/多节/AB 三种循环、对照跟练、课程进度和本地一键启动均纳入冻结范围。

## 本版关键交付

- 本地与部署形态统一使用 ffmpeg + librosa，消除两套 BPM 算法结果不一致。
- 移动端大文件使用 4 MB 幂等分块，解决单次大请求易失败问题。
- 修正分段边界：首节从 0 秒开始、尾节到媒体结尾、不足 8 拍仍保留。
- 拍点偏移确认后重新生成全量网格，首尾残片、列表、数拍和循环同步更新。
- 单节循环锁定显式目标，并提供前一拍/后一拍动作衔接。
- 多节连续块整体循环，非连续块按顺序轮转。
- AB 点吸附真实拍点并与其他循环引擎隔离。
- 单击播放/暂停；双击左/中/右为上一拍/全屏/下一拍。
- 左栏显示单节实际循环秒数和残缺拍号。
- Docker Compose 一键启动、自动打开 Docker Desktop、健康检查与持久化数据目录。
- 后端测试改用临时数据目录，杜绝测试误删真实课程。

## 非阻断提示

- 部分历史 React 测试会打印 `act(...)` timing warning，但断言全部通过。
- 后端有 3 条依赖弃用警告，不影响运行。
- Vite 报告约 563 KB JavaScript chunk；属于后续性能优化，不阻塞本地 v1。
- 完整 npm 依赖树报告 8 条公告；`npm audit --omit=dev` 的生产树为 2 条 React Router moderate、无 high/critical。应用只使用固定客户端路由且不做 SSR hydration；Router 7 大版本升级留待 v1.1 做完整回归。

## 已知限制

- 自动 BPM 与自动舞蹈第一拍不是同一问题；v1 仍需用户在少数视频上确认第一拍相位。
- 没有账号/云同步、姿态打分或 AI 动作反馈。
- URL 入口只适用于可直接下载的视频；公网部署前需补完整 SSRF 防护。
- 摄像头、语音、录制和全屏受浏览器平台能力影响。
- 本标签未自动推送到 GitHub，也不代表已经公开部署。
