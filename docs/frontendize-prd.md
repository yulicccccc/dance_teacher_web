## 0. 增量范围说明（本次改什么）

本次 PRD 只描述**相对 v0.1 的变更点**，未提及的现有需求（上传、8 拍分段、慢放、数拍、单节循环、镜像、进度保存、已学会标记等）**全部沿用 v0.1，不改动产品交互**。

| 维度 | v0.1（基线） | v0.2（本次增量） |
|---|---|---|
| 后端 | FastAPI（Python）+ librosa 做音轨提取与 beat 检测 | **移除**，全部逻辑移到前端 |
| 音轨提取 | 后端 ffmpeg/librosa 提取音频 | 浏览器内 `@ffmpeg/ffmpeg`（ffmpeg.wasm） |
| 节拍/BPM 检测 | librosa `beat_track` | 浏览器内 `essentia.js`（Essentia WASM） |
| 前端栈 | React + MUI + Tailwind | React + MUI + Tailwind（不变） |
| 部署 | 本地/容器运行后端 + 前端 | **纯静态产物**（vite build 的 `dist`）托管到 Cloudflare Pages |
| 运行成本 | 需服务器算力 | 零成本、零运维、免绑卡、无冷启动 |

## 1. 产品目标（前端化后给用户带来的价值）

**一句话定位**：打开网页即可用、无需等待服务器、完全免费——用户上传舞蹈视频后，所有音轨分析与分段都在自己浏览器里就地完成。

**3 条核心成功指标（关键结果，相对 v0.1 微调）**

| 指标 | 定义 / 目标值 |
|---|---|
| **指标1 · 即用性与零门槛** | 用户访问网页到可上传视频的时间 ≤ 页面加载完成即可用（无"等待服务器排队/启动"）；部署零成本、免绑卡、无冷启动。 |
| **指标2 · 本地处理时延与准确率** | 浏览器内完成"音轨提取 + 节拍检测 + 8 拍分段"：短视频（≤2 分钟）≤ 3 分钟得到可教学分段；分段抽检准确率 ≥ 90%（与 librosa 基线对齐，见待确认①）。 |
| **指标3 · 隐私与离线可用性** | 视频不离开用户浏览器（不出境、不上传服务器）；P2 阶段可离线打开网页继续使用。 |

**前端化新增的用户价值（对照 v0.1）**
- **打开网页即用**：无需部署/启动后端，刷新即用，无服务器等待。
- **无需等待服务器**：分析算力来自用户本机浏览器，不与他人争抢后端资源，无排队、无冷启动延迟。
- **完全免费**：静态托管 Cloudflare Pages 免费额度内零成本，用户无需付费，运营方无需养服务器。
- **隐私更优**：视频全程留在本机，仅本地处理（P0 起即满足）。

## 2. 用户故事（核心交互不变：上传 → 自动分段 → 慢放/数拍/单节循环）

> 下列故事沿用 v0.1 的核心路径，仅强调"无后端、本地处理"的流程变化。编号沿用 v0.1 故事语义，新增 FE 前缀标识前端化相关故事。

- **US-FE1（上传即本地处理）**：作为新手用户，我希望上传本地舞蹈视频后，网站**直接在浏览器里**完成音轨提取与节拍检测，而不需要把视频传到任何服务器，以便保护隐私、且不受服务器忙闲影响。
- **US-FE2（浏览器内 beat 检测）**：作为用户，我希望系统在浏览器内自动检测视频节拍/BPM（替代原后端 librosa），以便无需我手动打拍。
- **US-FE3（8 拍分段，不变）**：作为用户，我希望系统按"8 拍"把整支舞切成一个个小节（沿用 v0.1 P0-3 分段逻辑），以便一小节一小节地学。
- **US-FE4（分段慢放，不变）**：作为学不会的新手，我希望每个小节能单独慢放（0.5x / 0.75x），以便看清动作细节。
- **US-FE5（分段循环，不变）**：作为新手，我希望某个小节可以无限循环播放，以便反复跟练直到学会再进下一节。
- **US-FE6（节拍数叠加，不变）**：作为被带练的用户，我希望播放时屏幕上有"1、2、3…8"的节拍数和脉冲提示，以便踩准节奏。
- **US-FE7（进度保存本地，不变但更彻底）**：作为分多次学的用户，我希望学习进度保存在本机（localStorage/IndexedDB），即使在无后端环境下也能断点续学。
- **US-FE8（免费即用）**：作为不想付费的用户，我希望免费打开网页就能用全部功能，无需注册、无需等待服务器启动。

## 3. 需求池（P0 / P1 / P2）

> 标记「沿用」的需求来自 v0.1，本次仅做"去后端化"适配，交互与验收不变；标记「新增」为前端化带来的新需求。

### P0 —— 必须（前端化核心交付）

| 编号 | 描述 | 验收标准 |
|---|---|---|
| **P0-F1** | **浏览器内音轨提取**（替代后端） | 使用 `@ffmpeg/ffmpeg`（ffmpeg.wasm）从上传视频提取音频轨（如转码为 WAV/单声道）；提取失败时给出明确错误与重试；不依赖任何后端 API。 |
| **P0-F2** | **浏览器内节拍/BPM 检测**（替代 librosa） | 使用 `essentia.js`（Essentia WASM）对提取音频做 rhythm / BPM / beats 检测，输出 BPM 与节拍点序列；数值需与 librosa 基线对齐（偏差见待确认①），分段抽检准确率 ≥ 90%。 |
| **P0-F3** | **8 拍分段（沿用 v0.1 P0-3 逻辑，去后端）** | 前端按节拍点聚合为 8 拍小节，返回每小节时间区间与节拍点列表；短视频处理 ≤ 3 分钟；无后端调用。 |
| **P0-F4** | **教学播放页交互保留（沿用 v0.1 P0-4~P0-8）** | 小节列表、0.5x/0.75x/1x 慢放、单节循环、节拍计数叠加、镜像翻转等交互全部保留，行为与原版一致。 |
| **P0-F5** | **纯静态构建** | 通过 Vite 构建产出纯静态 `dist`（HTML/CSS/JS/WASM/worker 资源），不含任何服务端运行时代码；`vite build` 可本地成功产出。 |
| **P0-F6** | **Cloudflare Pages 部署** | 将 `dist` 部署到 Cloudflare Pages：零成本、免绑卡、无冷启动；配置正确的构建命令与输出目录；WASM / SharedArrayBuffer（ffmpeg.wasm 多线程所需）的 COOP/COEP 响应头正确设置。 |
| **P0-F7** | **隐私声明（沿用 v0.1 待确认⑦）** | 上传页明确声明"视频仅在你的浏览器内处理，不上传任何服务器"。 |

### P1 —— 增强（大视频/长视频与体验）

| 编号 | 描述 | 验收标准 |
|---|---|---|
| **P1-F1** | **大/长视频内存与性能处理** | 对大文件/长视频采用切片/流式处理、及时释放中间对象（如 `URL.createObjectURL` 回收、Transferable 内存回收）；监控内存占用，超限给出友好提示而非崩溃。 |
| **P1-F2** | **检测进度可视化** | 在浏览器处理期间展示分阶段进度（加载 ffmpeg/essentia → 提取音轨 → 节拍检测 → 分段 → 生成标注），并提供可取消/重试。 |
| **P1-F3** | **essentia.js / ffmpeg.wasm 资源懒加载** | WASM 与模型资源按需加载（首屏不阻塞），展示加载进度，降低首屏白屏（关联待确认③）。 |
| **P1-F4** | **分段微调（沿用 v0.1 P1-3）** | 用户可拖动边界微调小节起止，校正自动分段误差（浏览器内完成）。 |

### P2 —— 远期

| 编号 | 描述 | 验收标准 |
|---|---|---|
| **P2-F1** | **离线可用（PWA）** | 通过 Service Worker + Web App Manifest 支持离线打开网页、缓存静态资源，无网络也能使用已分析过的课程。 |
| **P2-F2** | **检测结果本地缓存** | 已分析的 BPM/节拍点/分段结果存入 IndexedDB，下次打开同视频免重复计算、直接恢复课堂。 |
| **P2-F3** | **我的课程列表（沿用 v0.1 P1-4）** | 已分析视频以课程卡片聚合于本地，可重开继续学（前端本地索引）。 |

## 4. UI 设计稿说明（保持现有界面与交互）

**原则**：v0.1 的全部界面（上传页、分析进度页、教学播放页、个人学习进度页）与设计要点**保持不变**。本次仅需在流程与文案上体现"无后端、本地处理"的变化，外观与布局不重构。

### 4.1 关键流程变化点

1. **上传页**：上传按钮文案/提示改为"视频仅在你的浏览器内处理，不上传服务器"；移除任何"发送到服务器分析"的暗示。保留本地文件选择（首版建议仍以本地文件为主，链接转码因跨域/CORS 在无后端下受限，见待确认⑤）。
2. **分析进度页（Analyzing）**：
   - 原后端步骤"接收视频 → 检测节拍 → 分段 → 生成标注"，改为浏览器内步骤："加载分析引擎 → 提取音轨(ffmpeg.wasm) → 检测节拍(essentia.js) → 8 拍分段 → 生成标注"。
   - 首屏需先"加载分析引擎"（ffmpeg.wasm + essentia.js WASM）并显示加载百分比（对应 P1-F2/P1-F3）。
   - 增加"取消"按钮，处理中可中止。
3. **教学播放页（Classroom）**：**完全沿用 v0.1 6.3 布局与控件**，不作 UI 改动；底层数据源从"后端返回"变为"浏览器内生成"，对用户界面无感知差异。
4. **个人学习进度页**：沿用 v0.1 6.4；数据来源改为本地索引（P2-F3）。

## 5. 待确认问题（风险点）

1. **essentia.js 与 librosa 数值对齐差异**：两者 beat/BPM 算法不同，同一视频分段结果可能不一致，是否影响"8 拍分段"教学准确性？建议：抽 5–10 段样本做对齐对比，设定可接受的 BPM/分段偏差阈值；偏差过大时回退到"固定 8 拍 / 手动标第一拍"兜底（沿用 v0.1 待确认①）。
2. **浏览器跑大视频的内存/CPU 上限**：ffmpeg.wasm 与 essentia.js 均为 CPU/WASM 密集，长视频（>5 分钟 / >200MB）可能 OOM 或卡死。建议：明确单文件上限（沿用 v0.1 建议 ≤500MB、≤10 分钟），P1-F1 做切片与内存回收，超限友好提示。
3. **ffmpeg.wasm 体积与加载耗时**：ffmpeg.wasm core 约 30MB+、essentia.js 模型亦不小，首屏加载可能慢、影响"打开即用"体验。建议：按需懒加载（P1-F3）、展示加载进度；评估多线程版（需 COOP/COEP）提速与兼容性权衡（关联 P0-F6 响应头）。
4. **移动端兼容性**：iOS Safari 对 WASM、SharedArrayBuffer、大内存支持有限，可能无法跑 ffmpeg.wasm 多线程。建议：先锁定桌面端（Chrome/Edge/Firefox）为 P0 目标，移动端作为已知限制并在上传页提示；P2 再评估。
5. **视频链接（非本地文件）支持**：无后端后无法服务端下载/转码外链视频，跨域 CORS 限制下浏览器直接拉取并 ffmpeg 处理可能失败。建议：首版（P0）仅支持本地文件上传，链接功能暂缓或仅支持允许 CORS 的来源。
6. **SharedArrayBuffer 与 Cloudflare Pages 响应头**：ffmpeg.wasm 多线程依赖 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: require-corp`。Cloudflare Pages 自定义头是否可配？建议：在部署配置中显式设置，否则退化为单线程模式（更慢但兼容）。
