## 1. 架构选型（P0 · 待用户决策）【最关键】

### 1.1 两条路线
- **路线 A — 纯浏览器（零后端）**：上传 / 解码音频 / 估 BPM / 切分全部浏览器本地完成（WebWorker 跑 `beat-detection`）。无服务器、无终端、永久在线。
- **路线 B — 后端 FastAPI + librosa**：前端把视频/音频传给后端，后端用 `ffmpeg`+`librosa` 检测 BPM、切分，前端轮询结果。Docker 单容器同源部署。

### 1.2 对比矩阵
| 维度 | 路线 A 纯浏览器 | 路线 B 后端 |
|------|---------------|------------|
| 部署形态 | CloudStudio 静态站（`frontend/dist`） | Docker / Render（uvicorn 同端口托管前端 + `/api`） |
| 运维负担 | **零**常驻进程 | 需常驻服务；Render 冷启动有唤醒延迟 |
| BPM 准确度 | `beat-detection`（纯 JS）实测可用；手动填 BPM 兜底 | `librosa`（业界标准）更稳，尤其真实 iPhone **MOV** |
| 离线可用 | ✅ 完全离线 | ❌ 需服务器（本地 Docker 除外） |
| 隐私 | ✅ 视频不出本机 | ⚠️ 视频上传服务器（本地 Docker 可缓解） |
| 大视频压力 | 内存 / 主线程（已在 WebWorker 隔离） | 服务端算力，前端无压力 |
| 复杂度 | 无服务端 | 全栈（Dockerfile 多阶段、requirements、ffmpeg 系统依赖） |
| 与用户偏好 | ✅ 符合「零服务器、零终端、永久在线」 | ❌ 违背 |

### 1.3 Codex 回退理由 vs 待验证点
Codex 在 `requirements-audit.md` 写道：「‘零后端’是技术假设，已被真实 iPhone MOV 验证否决」。
**待验证**：① 纯浏览器 `beat-detection` 对真实 MOV 到底准不准？② 若有偏差是参数问题（可纯浏览器内修）还是必须 librosa？③ 仅为一类格式牺牲用户明确偏好的「零后端」是否值得？
> **建议（中立）**：两条路线循环 UX 完全等价（循环逻辑是前端 `useBeatSync`，与音频来源解耦）。先各试一段真实 MOV 用数据决策。

### 1.4 决策影响
- 选 **A**：revert Codex 音频回退（`frontend/src/audio/*`、`api/localAnalysis.ts`、`hooks/useLocalAnalysis.ts`、`workers/*` 恢复），保留循环 v2；恢复 CloudStudio 静态部署。
- 选 **B**：维持现状，部署走 Docker/Render；放弃 CloudStudio 静态站与零后端形态。
- 循环 v2 代码（ControlBar / SegmentList / lessonStore / useBeatSync）**两种路线都保留**，不受影响。

## 2. 产品全貌（来自总规划 v0.1）

### 2.1 一句话定位
把任意舞蹈视频，自动变成「舞室老师一小节一小节带练」的智能教学课——用户上传视频，剩下的交给网站。

### 2.2 核心成功指标（KR）
| 指标 | 定义 / 目标 |
|------|------------|
| KR1 处理时延与准确率 | 上传后本地算力下 ≤3 分钟（≤2 分钟短视频）得「可教学 8 拍分段 + 节拍标注」；分段抽检准确率 ≥90% |
| KR2 学习完成度 | 新手单支舞「分段学习完成率」≥70%；断点续学保存率 100% |
| KR3 带练有效性 | 单小节「带练→学会→下一节」转化率 ≥60%（以循环次数 + 已学会标记衡量） |

### 2.3 目标用户
18–35 岁、想自学舞蹈但「看视频学不会」的零基础小白。动机：学爱豆/K-pop/热门舞、聚会表演、健身。痛点：视频太快、无节拍提示、不知对错、没人带练、易放弃。设备：笔记本/台式机浏览器（Phase1）；带摄像头设备（Phase2）。

### 2.4 典型场景
- **小美**：下载 K-pop 视频 → 上传 → 按 8 拍拆 12 节 → 从第 1 节慢放+循环，跟「1、2…8」口令练，学会点下一节。
- **阿杰**：老师背面教学视频用「镜像翻转」当正面示范，逐节攻克。
- **回归学习**：学到第 6 节关网页，下次打开自动回到第 6 节。

### 3.6 镜像体系（视频镜像 / 拍点镜像 分离）【用户重点诉求 · v3 已补，本版坐实】
**用户原话诉求**：「镜面翻转视频」和「镜面翻转拍子」要**分开**——两个独立开关，不能绑一起。
**为什么必须分开**（教学场景本质）：学舞时希望视频左右翻转成镜面视角（老师左手对应你左手）；但拍点提示（数拍数字/脉冲）若也翻转，数字变反、对齐乱，反而干扰读拍。故「翻视频」与「翻拍点」正交，可任意组合。
**已实现的两个独立状态（store/lessonStore.ts）**：
| 状态字段 | 控制按钮 | 默认 | 作用范围 | Tooltip |
|---------|---------|------|---------|---------|
| `mirror` | 视频镜像 | `true` | **仅**翻转 `<video>` 像素（`scaleX(-1)`） | 仅翻转视频画面 |
| `beatMirror` | 拍点镜像 | `true` | **仅**翻转 `BeatOverlay`（数拍数字+脉冲点随之翻转） | 独立翻转拍点提示，不影响视频画面 |
**关键不变量**：① `mirror` 与 `beatMirror` 完全独立，改一个绝不影响另一个；② 二者只翻视觉像素，不改变时间轴/拍点索引/双击语义；③ 双击左/右半屏跳拍不受任一影响；④ 数拍脉冲 rAF 同步逻辑与镜像无关。
**第三个镜像上下文（CompareMode 对照）**：`CompareMode.tsx` 自带 `mirror` prop，作用域仅限对照分屏（左 TV + 右摄像头两半都翻，便于对齐比较），与上面两个全局开关独立；对照模式下全局镜像不生效（避免双重翻转）。
**验收标准**：① 默认视频镜像=开、拍点镜像=开；② 仅关视频镜像→画面正、拍点仍翻（反之亦然），互不影响；③ 4 种组合均可独立设置并持久化；④ 双击跳拍在 4 种组合下一致；⑤ 对照模式自带镜像独立工作，不与全局串扰。
**待确认 Q6**：左栏小节列表（SegmentList）当前不随拍点镜像翻转（「拍点镜像」只翻 BeatOverlay）。是否需让左栏也独立镜像？→ 待用户定。

## 4. 循环重设计详细（单开关 + 三模式 + 复用左栏）

### 4.1 交互设计稿
控制栏（ControlBar）目标形态：
```
[ 循环 ]  ← 唯一总开关，固定文案；开启=contained，关闭=outlined；多节未选时置灰
 ( single | multi | ab )  ← 三选一 ToggleButton，互斥
 ── 摘要行 ──
 循环已关闭 / 循环中·单节(第N节) / 循环中·多节(第1-3,5节) / 循环中·AB(A→B)
 ── AB 模式专属 ──
 [设A][设B]  A: 00:12.3  B: 00:18.7  [清除]
 [循环次数: 无限 ▾]
```
左侧小节列表（SegmentList）目标形态（**多节模式才出现勾选框，单节/AB 不出现**）：
```
单节/AB 模式：               多节模式：
┌──────────────┐            ┌─╮──────────────┐
│ ① 第1节      │            │☑│ ① 第1节      │
│ ② 第2节      │            │☑│ ② 第2节      │
│ ③ 第3节  ◀当前│            │║│ ③ 第3节  ◀当前│
│ ④ 第4节      │            │☐│ ④ 第4节      │
└──────────────┘            │☐│ ⑤ 第5节      │
                            └─╯──────────────┘
                            [全选] [清空]
```
> **删除右侧重复 `LoopPanel`**：多节勾选只在左栏出现，杜绝「两处都有列表」的混乱（用户原话："这样的操作非常不直觉"）。

双击播放器手势：**屏幕右半 = 后一拍（stepBeat(+1)）；屏幕左半 = 前一拍（stepBeat(-1)）；屏幕中区 = 全屏**。纯屏幕坐标，**不受 `mirror`/`beatMirror` 影响**（镜像只翻视频/拍点像素，不改屏幕空间意图）。

### 4.2 状态模型（store/lessonStore.ts）
```ts
type LoopMode = 'single' | 'multi' | 'ab'
interface LessonState {
  loopEnabled: boolean          // 总开关（唯一语义：循环是否启用）
  loopMode: LoopMode            // 三选一，互斥
  loopSegmentIds: number[]      // 多节模式下勾选的小节 id（升序、去重）
  abLoop: ABLoop | null         // { aTime, bTime } 拍点对齐；aTime<bTime 才有效
  loopCount: number | null      // 循环次数上限（null=无限）
  mirror: boolean               // 视频镜像（独立）
  beatMirror: boolean           // 拍点镜像（独立）
}
```
**与旧字段迁移**：旧 `loopSegment: boolean` ≡ `loopEnabled && loopMode==='single'`；旧 `abLoop.enabled` 合并进 `loopEnabled && loopMode==='ab'`。本地进度（`useLocalProgress`）需做字段映射，避免老用户存档失效。
**关键不变量**：切换 `loopMode` 只改 store，**不 seek、不暂停**；`loopEnabled` 关闭时引擎完全不干预播放。

### 4.3 验收标准（可执行）
1. 默认进入：按钮「循环」=outlined（关），模式=single。
2. 单节模式：点左栏任意小节 → 跳到该节 + 自动开启循环（循环该节，前后各一拍过渡）。
3. 多节模式 + 未勾选：主开关置灰（disabled），hover 提示"请先勾选要循环的段落（在左侧小节列表）"。
4. 多节模式 + 勾选 [1,2,3,5]：连续 [1,2,3] 合并成一个块（前后各一拍），[5] 自成一块；块间按序轮转。（注：用户首选"前后各加一拍"；并授权"若一拍太难，前后各加 1 秒也行"为降级兜底。）
5. AB 模式：仅 AB 模式显示设 A/设 B；aTime≥bTime 时开关禁用。
6. 单节/AB 模式下，左栏**不显示**勾选框。
7. 双击左半=前一拍、右半=后一拍、中半=全屏，镜像开/关行为一致。
8. 循环状态摘要文案随模式/选择动态变化；多节显示区间折叠（如"第1-3,5节"）。
9. 多节清空勾选 → 自动关闭循环。
10. 切换模式不 seek、不暂停；刷新后循环 v2 状态从本地恢复。

### 4.4 复用左栏的边界
- 多节模式：左栏每项 = 文字（点击=跳转）+ checkbox（点击=勾选），**双热区互不串扰**（点 checkbox 不触发跳转）。
- 单节/AB 模式：左栏只显示文字，无 checkbox。

## 5. 实现方案与踩坑（给 Codex）

> 以下均经实测，附「给 Codex 的提示」，便于维护/修改时不踩同坑。

### 5.1 路线 A 纯浏览器（若 §1 选 A，需恢复）
- **解码**：`audio/decodeAudio.ts` 用 `OfflineAudioContext` 取单声道 PCM。
- **检测**：`audio/beatDetectionDetector.ts` 跑 `beat-detection`（`detect(pcm,{fs,minBpm,maxBpm})` → `{bpm,confidence,beats}`）；失败回退 `audio/gridOnlyDetector.ts`（ACF 自相关 + 均匀网格 + 首拍取最强 onset，零依赖）。
- **线程**：`workers/beat.worker.ts`（Vite `base:'./'` + `worker.format:'es'`）隔离主线程。
- **坑 A1**：**绝不要用 `aubio.wasm`**——npm 包不发包 `aubio.wasm`，本地无 emscripten 工具链，实测不可行。
- **坑 A2**：`beat-detection` 对部分 MOV/高采样率可能偏差，需调 `minBpm/maxBpm` 或加 grid 兜底；真实 MOV 准确度是 §1.3 待验证项。
- **坑 A3**：视频源三级回退 `DEMO_VIDEO_URL` → `videoRegistry` objectURL → IndexedDB；`computeVideoId` 必须与旧 `Uploader` 逐字节一致。

### 5.2 路线 B 后端（当前代码，若 §1 选 B 维持）
- **栈**：FastAPI + `librosa` + `soundfile` + `ffmpeg-python`；`ANALYSIS_SR=22050, HOP_TRACK=256, HOP_FINE=128`。
- **坑 B1**：`librosa` 拉 `numba/llvmlite`，Python 3.13 本地需编译器；**Dockerfile 用 `python:3.11-slim` 规避**。一律走 Docker。
- **坑 B2**：`octave` 裁决搬到点周期上（`OCTAVE_F_MARGIN=0.15`），不变量 `60/median(diff)==bpm` 结构性成立；`RECOVER_CEIL_BPM=260` 解耦恢复上限与 `FAST_BEAT_BPM`（220/240 快歌恢复全速）。
- **坑 B3**：176–204 BPM 曾报半速，用低频 onset 包络加密门修复（带限 30–250Hz、双条件 `ratio>=0.55 && contrast>=8.0`）。
- **坑 B4**：前端 `api/client.ts` base = `import.meta.env.VITE_API_BASE ?? '/api/v1'`；后端 `main.py` 用 `StaticFiles` 托管 `frontend-dist` + SPA fallback。
- **坑 B5**：大文件上传分块（4MB）、幂等、自动重试。

### 5.3 循环引擎 useBeatSync（两种路线共用，已稳定）
- **坑 C1（单节竞态）**：点小节切换循环目标时，rAF tick 可能在 `seeked` 前运行，旧逻辑用旧目标 padded loopEnd 误判回跳（"卡在当前小节"）。修复：`forceLoopTargetRef` 在 seek **前**写入目标小节 index，tick 每帧最开头消费；**多节模式不消费该 ref**。
- **坑 C2（镜像方向）**：双击 `stepBeat` 必须**忽略 `mirror`**。曾因 `onDoubleClick` 按 mirror 反转折磨用户，已修。
- **坑 C3（AB 互斥）**：AB 与单节循环互斥；`abLoopRef` 仅在 `loopMode==='ab' && loopEnabled` 时驱动 AB 引擎。
- **坑 C4（多节合并）**：`buildLoopBlocks(segments, ids)` 把连续 id 合并成块；`computePaddedLoopBoundsForBlock` 块首 −1 拍 / 块尾 +1 拍，边界 clamp；非连续块按序轮转。
- **坑 C5（双击不置 seekingForLoopRef）**：`stepBeat` 有意不置 `seekingForLoopRef`，否则会被循环引擎立刻拽回；只 `set currentTarget + pause`。
- **坑 C6（偏移草稿）**：拍点偏移用"草稿值→重新计算拍子→确认"两段式，拖动时不破坏当前循环目标。
- **坑 C7（双击三区全屏）**：双击中区 = 全屏（非跳拍），需与左右跳拍区互斥判定，且**全屏不受镜像影响**（屏幕坐标）。
- **坑 C8（首尾残缺小节）**：偏移后的第一个完整 8 拍之前、最后一个完整 8 拍之后都属于有效视频内容，不能因不足 8 拍丢弃。`resegmentSegments` 保留两端、覆盖 `0..duration`，首段用 `startBeat` 显示真实计数；确认偏移时当前节按播放头重定位，多节选择/旧已学标记因语义失效而清除，AB 保留物理时间并刷新显示位置。

### 5.4 测试注意（flaky）
- 完整并行 suite 下偶发计时器抖动失败（如 `compareMode` "录制中 elapsed badge"），**隔离运行稳定**。属测试环境噪声，非回归。
- 跑测试务必 `cd frontend && npm run test`（本地 `./node_modules/.bin/vitest`）。根目录旧 `vitest.config.ts` 会干扰；`npx vitest` 会误装全局 `vitest@4` 报错。
- bash cwd 不跨命令保持，每条命令自带 `cd frontend &&`。

## 8. 给 Codex 的核心不变量（修改时务必保持）

1. `60 / median(beat_intervals) == bpm`（BPM 与网格周期一致，杜绝八度错位）。
2. 切换 `loopMode` **不 seek、不暂停**。
3. `loopEnabled=false` 时引擎零干预。
4. 单击小节文字=跳转；多节模式点 checkbox=勾选；双热区互不串扰。
5. 双击：左半=前一拍、右半=后一拍、**中半=全屏**，**不受 mirror/beatMirror**。
6. 视频镜像（`mirror`）与拍点镜像（`beatMirror`）是两个**独立开关**，互不影响；二者都只翻渲染像素，不翻时间轴/拍点索引/双击语义（见 §3.6）。
7. 单节循环含前后各一拍过渡；多节连续合并 + 前后各一拍；非连续分块轮转。
8. AB 与单节互斥；AB 仅在 `loopMode==='ab' && loopEnabled` 时驱动。
9. 部署若走 A：纯静态；若走 B：Docker 同源。禁止"前端静态 + 后端分离"的半吊子。
10. 任何重构/回滚都不得丢失 §3 已落地功能（全屏、对照、我的课程、学习统计、内置示例、循环次数、键盘快捷键、语音数拍等）。
