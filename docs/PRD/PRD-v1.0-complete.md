## 1. 产品定义

### 1.1 一句话定位

把任意舞蹈视频自动变成一门可以像在舞室里一样，按 8 拍、小节、慢速和循环反复练习的本地网页课程。

### 1.2 v1 解决的问题

- 普通教学视频太快，学习者很难看清动作和跟上节拍。
- 手工拖进度条难以稳定回到同一拍，首尾也缺少动作衔接。
- BPM 即使正确，舞蹈的“第一拍”仍可能与算法选定的节拍相位不同。
- 浏览器、本地服务和部署环境使用不同分析链路时，结果会不一致。
- 手机上传大 MOV 容易在单次请求、代理或解码环节失败。

### 1.3 目标用户与场景

核心用户是想跟视频自学舞蹈、但跟不上原速或难以自己找拍的初学者。典型使用方式包括：学习 K-pop/短视频舞蹈、把背面示范镜像成易模仿视角、逐节完成一整支舞，以及隔天从上次位置继续练。

v1 的产品判断指标是：能否在一次上传后产出可练习的小节；用户能否依靠减速、数拍和循环学会并标记小节；关闭网页后能否完整恢复学习位置。BPM 抽检准确度与第一拍相位应分别记录，不能用“BPM 正确”代替“小节第一拍正确”。

### 1.4 v1 核心原则

1. **一条分析链路**：本地和部署版都使用 FastAPI + ffmpeg + librosa，避免浏览器算法和服务端算法产生两套结果。
2. **一个节拍网格**：列表、数拍、跳转、六档循环和 AB 锚点都读取同一份已确认网格。
3. **BPM 与第一拍分离**：BPM 决定拍间距；第一拍/8 拍相位决定小节边界。两者必须分别允许人工纠正。
4. **首尾不丢帧**：即使开头或结尾不足 8 拍，也必须保留为残缺小节并覆盖完整视频。
5. **循环目标锁定**：自动跳回不能被误判为用户跳转，也不能在前导拍阶段把目标串到上一节。
6. **本地优先**：v1 的标准交付是本机 Docker 版；视频和课程数据不依赖第三方云服务。
7. **练习与录像一致**：对照现场和下载视频使用同一拍数、口令、镜像状态与老师时间线，不依赖无法录入的 DOM/TTS 旁路。

### 1.5 完成标准

- 用户能上传一段视频并得到 BPM、拍点与按 8 拍划分的小节。
- 用户可人工修正 BPM 或第一拍相位，所有依赖节拍的功能同步重算。
- 当前、前节、后节、单节、多节、AB 六档循环都能反复运行，不随机跳拍或跳到别的小节。
- 开头、结尾以及偏移后形成的不足 8 拍小节仍可播放和循环。
- 对照录制的现场与下载文件保留当前 1–8 拍数；口令开启时也保留口令和老师原声。
- 录制前可决定写入视频的镜像，录制后可独立翻转回看视图。
- 课程进度可恢复，本地启动不需要手工分别启动前后端。

## 2. 最终架构决策

### 2.1 决策

v1 固定采用 **React 前端 + FastAPI 后端 + ffmpeg/librosa 分析 + 单 Docker 容器**。不再把“纯浏览器分析”保留为当前待决定方案。

原因：真实 iPhone MOV、移动端大文件和复杂音乐需要与本地高准确版本一致的解码与分析环境。纯静态 Pages 无法运行 Python/librosa，曾经的浏览器端检测与后端结果也无法保证一致。

### 2.2 运行拓扑

```text
浏览器
  ├─ React SPA：上传、分析进度、课程与学习状态
  └─ /api/v1/*、/api/v1/video/*
                 │
                 ▼
FastAPI（同一 8000 端口）
  ├─ 上传校验、分块合并、任务状态持久化
  ├─ ffmpeg 抽取 PCM WAV
  ├─ librosa/NumPy 检测 BPM 与拍点
  ├─ 8 拍聚合与重算
  └─ 提供 React 构建产物和 SPA deep-link fallback
                 │
                 ▼
backend/data/{uploads,wav,tasks}
```

### 2.3 技术栈

| 层 | v1 技术 |
|---|---|
| Web | React 18、TypeScript、Vite 5、MUI 5 |
| 状态 | Zustand；localStorage + IndexedDB |
| API | FastAPI、Pydantic、Uvicorn |
| 音视频 | ffmpeg/ffprobe、librosa、soundfile、NumPy、numba |
| 打包 | Node 22 构建前端，Python 3.11 运行后端，多阶段 Dockerfile |
| 本地编排 | Docker Compose，项目数据目录挂载，numba 缓存卷 |

## 3. 用户流程与页面

### 3.1 路由

| 路由 | 页面 | 用途 |
|---|---|---|
| `/` | 上传页 | 选择本地视频、粘贴直链或打开内置示例 |
| `/analyze/:taskId` | 分析页 | 显示四阶段进度、失败原因和重试 |
| `/lesson/:taskId` | 教学页 | 播放、数拍、六档循环、校准与跟练 |
| `/progress` | 我的课程 | 继续学习、查看已学小节和练习时长 |

未知前端路由返回首页；生产服务对已有 SPA deep link 返回 `index.html`。未知 `/api/*` 仍返回 404，不得被 SPA fallback 吞掉。

### 3.2 主流程

1. 用户上传本地视频或提供可直接下载的视频 URL。
   上传页会先探测/唤醒服务；冷启动期间显示明确状态，不让用户误以为页面无响应。
2. 前端根据文件大小选择普通上传或分块上传。
3. 后端立即创建任务并异步执行抽音频、拍点检测和分段。
4. 前端每秒轮询任务状态；成功后进入教学页，失败可重试。
5. 用户核对 BPM 和第一拍；必要时手填 BPM、重新自动检测、固定 120 BPM、指定第一拍时间或调整拍点偏移。
6. 用户选择速度、镜像、语音数拍与循环模式练习，标记已学会。
7. 下次打开课程时恢复学习状态。

## 4. 上传与分析

### 4.1 文件输入

- 支持拖放或点击选择 `mp4`、`webm`、`mov`。
- 最大 500 MB，最长 10 分钟；后端使用扩展名、文件大小和 ffprobe 时长再次校验。
- 小于等于 8 MB 使用 multipart；大于 8 MB 使用 4 MB 分块。
- 分块按顺序提交，每块最多自动重试 3 次，指数退避从 500 ms 开始。
- 已成功接收的块可幂等重试；中断写入回滚到最后提交的字节边界。
- 完成请求也幂等，响应丢失后重试不会创建重复分析任务。
- 24 小时以上的未完成上传会清理。

### 4.2 URL 输入

- 接受后端可直接下载的视频 URL，下载后走与本地上传完全相同的校验和分析。
- v1 不承诺解析视频网站分享页、登录页或受 DRM 保护的视频；应使用文件或真实媒体直链。
- 公网投产前仍需增加 URL 白名单/SSRF 防护和流式字节上限，见 §14。

### 4.3 分析状态

`queued → extracting → beat_detecting → segmenting → done`，任何阶段可进入 `failed`。任务状态、结果和错误持久化到 JSON，因此服务重启后仍可查询。

### 4.4 音频处理

- ffmpeg 从原视频抽取标准 PCM WAV，避免 MOV/WebM 浏览器解码差异。
- FastAPI lifespan 在主线程预热 librosa/numba，避免第一次分析在守护线程里触发 JIT 后卡死于 `beat_detecting`。
- 单次拍点检测有 `max(60 秒, 音频时长 × 3)` 超时保护。

### 4.5 BPM 与拍点检测

- 分析采样率 22050 Hz；追踪 hop 256，细化 hop 128。
- 使用 onset envelope、librosa beat tracking、网格拟合与相位评分生成均匀拍点网格。
- 同时用 120 BPM 与 180 BPM 两个先验追踪候选节奏层，按 onset 匹配度减去拍间抖动做裁决；快候选仅需比主候选高出 `0.05` 才可替换，避免先验轻微变化造成结果翻转。
- 当更稳定的快候选与原候选不是半速/双速关系时，视为“密集打击乐层与主脉冲竞争”：选中快主脉冲后取更强的半速相位作为舞蹈计数 BPM。若两个候选明确为 1×/2×，保留真正快歌，不重复减半。
- 对半速/双速误判做 octave correction，频率裁决余量 `OCTAVE_F_MARGIN=0.15`；快 BPM 恢复上限 `RECOVER_CEIL_BPM=260`，不与普通快歌阈值耦合。
- 对强高频素材增加 30–250 Hz 低频 onset 的快 BPM 恢复路径；仅在候选得分比 `≥0.55` 且对比度 `≥8.0` 时采用，避免无条件把节奏翻倍。
- 置信度不是“网格规则度恒等于 1”；网格路径按真实 onset 与拍点的匹配质量计算。
- 置信度低于 0.6 时前端显示校准提示。
- 结果必须满足 `BPM = 60 / median(相邻拍点时间差)`，防止显示 BPM 与实际网格不一致。

### 4.6 四种重新分析/校准方式

| 模式 | 行为 |
|---|---|
| 自动 | 再次运行完整检测 |
| 固定 120 | 从 0 秒生成 120 BPM 规则网格 |
| 手填 BPM | 接受 40–300 BPM，按用户值生成规则网格 |
| 手动第一拍 | 以用户输入的秒数为锚点，沿当前 BPM 生成规则网格 |

教学页始终显示当前 BPM 和置信度，不应只在低置信度时才允许手动修正。

## 5. 小节与第一拍校准

### 5.1 服务端初始分段

- 每 8 个拍点组成一个舞蹈小节。
- 第一小节从 0 秒开始，拥有第一个拍点之前的前奏/无拍区。
- 最后一小节延伸到媒体真实结束时间。
- 最后不足 8 拍仍输出为小节，不能丢弃。
- 恰好等于媒体时长的拍点只作为结束边界，不创建零时长小节。

### 5.2 拍点偏移

用户可选择 -4 到 +4 个整数拍的偏移。UI 使用“草稿 → 重新计算拍子”两段式操作；拖动草稿不会立即打乱正在播放的课程。

确认偏移后，前端从原始拍点重新生成整份小节网格，而不是只给时间加一个常数：

- 以 `((offset % 8) + 8) % 8` 决定新的完整小节起点。
- 新第一拍之前保留为前导残缺小节，显示真实拍号，例如 `5–8拍`。
- 末尾不足 8 拍保留为尾部残缺小节。
- 整个网格始终覆盖 `0..duration`，不能因为没有完整 8 拍而裁掉开头或结尾。
- 节拍时长从全部相邻拍点的中位数推导，不能拿首尾被拉长的小节时长反推。

### 5.3 校准后的状态处理

- 当前播放位置重新映射到新网格中的小节。
- 旧的多节数字选择清空，因为原小节编号语义已变化。
- “已学会”标记清空，避免把旧编号错误映射为新动作。
- AB 循环保留真实时间点，并刷新显示用的拍点编号。
- 数拍、列表、上一/下一小节与六档循环立即读取新网格。

### 5.4 能力边界：BPM 不等于舞蹈第一拍

自动 BPM 可以很准，但仅凭通用音频 onset 无法保证选中编舞者定义的每组 8 拍第一拍。一个稳定 BPM 网格存在 8 种小节相位，音乐重音、前奏、切分音与编舞起点也可能不同。

因此 v1 的可靠闭环是：自动找 BPM 和细拍点，用户只需确认/移动第一拍相位；确认后所有功能统一重算。未来可以增加 downbeat/phrase 模型与“把当前拍设为 1”快捷操作，但不能把其未实现误写成 v1 已完全自动解决。

## 6. 教学播放器

### 6.1 基础播放

- 中央播放/暂停按钮、进度条拖动、上一/下一小节。
- 速度范围 0.25×–1.5×；一键恢复 1×。
- 当前小节在左栏高亮，进入新小节时自动同步。
- 视频画面镜像与拍点叠加层镜像相互独立，默认都开启。

### 6.2 通用画面手势

- 单击视频画面：播放/暂停。
- 双击左侧三分之一：上一拍。
- 双击中间三分之一：进入/退出全屏。
- 双击右侧三分之一：下一拍。
- 镜像只改变画面，不反转左/右手势语义。
- 单击延迟 220 ms 执行，以区分双击；控件和拍点圆点必须阻止事件冒泡。

### 6.3 键盘与全屏

- 播放器获得焦点后，Space、Enter、K 切换播放/暂停。
- `,`（逗号）移动到前一拍，`.`（句号）移动到后一拍；使用物理键位识别，中文输入法下仍有效。
- 左/右方向键同样移动一拍；F 切换全屏。
- 标准 Fullscreen API 之外保留 WebKit fallback；iPhone 使用原生视频全屏 fallback。
- 手动逐拍会暂停，并按“用户跳转”处理，而不是误触循环自动回跳。

### 6.4 数拍与语音

- 画面左上方显示当前 `1–8` 大号拍数、脉冲动画和 8 个拍点圆点，尽量不遮挡老师主体动作。
- 点击拍点圆点跳到对应拍点，不触发画面单击。
- 叠加层由 `requestAnimationFrame` 与媒体时间同步，不依赖粗粒度 `timeupdate`。
- 口令使用本地 `public/voice-counts/1.wav`–`8.wav` 短采样，用户可独立开关；不再依赖操作系统 Web Speech voice。
- v1.2.1 的正式采样来自用户本人的连续 1–8 录音；按安静间隔切成 8 段，每段保留少量首尾缓冲并淡入淡出，平均音量统一为 -20 dB。`manifest.json` 保存源文件校验值、切分边界、增益与 8 个成品校验值。
- 同一个 Web Audio source 同时连接扬声器与对照录制混音总线，因此日常学习、录制现场和下载视频听到的是同一组口令。
- 口令开启后显示独立音量滑杆，范围为 0–200%、默认 100%；它只改变口令，不改变老师视频原声，并按课程保存。
- 口令 source 先经过同一个 `GainNode`，再分流到扬声器和录制混音总线，因此调节后的音量在学习、录制现场和下载视频中完全一致。
- 用户首次点开“口令”时在真实手势内解锁 AudioContext 并预加载 8 个短采样，避免浏览器自动播放策略吃掉第一拍。

### 6.5 学习动作

- 标记/取消“已学会”。
- 一键进入下一小节。
- 左栏显示每节时长、残缺拍号，以及前节/后节/单节循环的实际秒数。

## 7. 六档循环（v1.1 核心）

### 7.1 统一交互

- 只有一个固定文案“循环”的总开关。
- 模式按“当前 / 前节 / 后节 / 单节 / 多节 / AB”排列，六者互斥。
- 切换模式只改变配置，不应突然 seek 或暂停。
- 可选循环次数 3–10；空值表示无限循环。达到次数后不再回跳，继续向后播放。
- 对照练习和录制复用同一个老师视频，因此六档循环继续生效；不能因为开始录制就让老师视频脱离循环。

### 7.2 当前：三拍动作循环

用于只抠一个很难的动作。以启用时播放头所在拍为“当前拍”，循环：

```text
当前拍的上一拍 → 当前拍 → 当前拍的下一拍
```

实现上结束边界取“下一拍之后的拍点”，确保三拍都完整播放。用户拖进度条、逐拍跳转或点击小节后，会把当前动作重新锁到新的真实拍点；程序自动回跳不能触发重新锁定。位于视频第一拍或最后一拍时按媒体边缘截断。

### 7.3 前节：前四拍练习

核心练习目标为当前小节第 1–4 拍，并各保留一拍动作衔接：

```text
上一小节第 8 拍 → 当前小节第 1–4 拍 → 当前小节第 5 拍
```

实现上到当前小节第 6 拍的时间戳才回跳，所以第 5 拍能完整播放。第一小节没有上一拍时从媒体开头开始。

### 7.4 后节：后四拍练习

核心练习目标为当前小节第 5–8 拍，并各保留一拍动作衔接：

```text
当前小节第 4 拍 → 当前小节第 5–8 拍 → 下一小节第 1 拍
```

实现上到下一小节第 2 拍的时间戳才回跳，所以下一节第 1 拍能完整播放。最后没有后续拍点时播放到媒体结尾。

### 7.5 单节循环

用户点击左栏某一节时：跳到该节并自动开启循环，且目标锁定为该节。

实际播放范围用于保留动作衔接：

```text
上一小节第 8 拍 → 目标小节第 1–8 拍 → 下一小节第 1 拍
```

实现上，结束边界是下一节第 2 个拍点；到达该边界后回到上一节第 8 拍。第一/最后小节没有足够上下文时按 0 秒或媒体结尾截断。

左栏在单节模式显示每一节的实际循环秒数，便于用户核对“到底循环哪里”。

### 7.6 多节循环

- 多节模式的勾选入口只在左栏，避免重复控制面板。
- 支持全选和清空；清空后自动关闭循环。
- 连续编号合并为一个播放块，例如 3、4、5 连续播放后整体回跳。
- 不连续编号形成多个块，例如 2、3 与 6、7，按时间顺序轮转。
- 每个块同样带一拍前导和一拍尾随，媒体边缘自动截断。
- 勾选与当前播放高亮是两种不同视觉状态；点击 checkbox 只选择，点击文字才跳转。

### 7.7 AB 循环

- A、B 都吸附到播放位置之前最近的真实拍点，而不是任意毫秒。
- 只有 `A < B` 时循环按钮可用。
- AB 模式且总开关开启时，AB 引擎优先于单节/多节。
- 偏移重算后保留 A/B 的真实时间，重新计算界面拍号。

### 7.8 循环引擎不变量

1. 自动回跳目标必须在 seek 前写入 `forceLoopTargetRef`，下一帧先消费强制目标。
2. 程序触发的回跳与用户拖动必须用独立 guard 区分。
3. 进入前导/尾随上下文拍后，前节、后节、单节的目标仍是用户选中的目标节，不能按播放位置串到相邻小节。
4. 循环开关从关到开时锁定当前/明确选择的目标。
5. 多节配置变化时重建块游标，并按当前播放位置重新锚定。
6. AB 判断具有最高优先级，不能同时运行另一循环分支。
7. 媒体 `seeked` 存在浏览器时间误差，落点容差约 0.1–0.35 秒，不能要求浮点完全相等。
8. “当前”锁定的是动作拍；只有真实用户 seek/逐拍/列表跳转才能换目标，自动回跳必须保持原动作。
9. 在当前/前节/后节/单节之间切换时保留明确选择的小节；播放头处在借来的上下文拍中也不能误锁相邻节。

## 8. 对照跟练

- 教学页内联开启摄像头，不使用会遮挡教学上下文的弹窗。
- 左侧老师、右侧学习者，画布输出 1280×720；“录制镜像”在开始录制时锁定，同时作用于两边画面并真正写入视频。
- 回看页另有“回看镜像”，只改变当前回看视图；界面明示下载文件是否已使用录制镜像，避免把两个含义混淆。
- 复用页面中同一个老师视频作为时间源，不创建第二个独立老师播放器。
- 拍数大字与 8 个拍点由每帧 Canvas 直接绘制在左上角，而不是另放一层 DOM，所以录制现场和下载视频都保留完全相同的拍数。
- 通过 `canvas.captureStream()` 和 `MediaRecorder` 录制画面；老师原声和本地口令先进入同一个 `MediaStreamAudioDestinationNode`，再只向录制器添加一条混合音轨。
- 口令关闭时混音轨只保留老师原声；口令开启时两者共存。浏览器不支持 Web Audio 时可降级为只录老师原声或无声视频，不阻塞录像。
- 录制持续到用户手动停止；支持回看、下载和重新录制。
- 开始、暂停或停止录制只控制录制器，不改变老师视频的循环配置或循环引擎状态。
- 关闭模式时停止摄像头 tracks，销毁 object URL，避免摄像头占用和内存泄漏。
- 实际编码格式由浏览器能力决定，Safari/iOS 兼容性属于平台限制。

## 12. 本地启动、停止与数据安全

### 12.1 一键启动

macOS 用户首选双击桌面的原生应用 `舞蹈老师.app`。应用不显示终端窗口，并在后台调用 `start_local.sh`：

1. 显示“正在启动”通知并转交给 `start_local.sh`；Finder 的精简 PATH 已兼容 Docker CLI。
2. 检查 Docker CLI；如 Docker Desktop 未运行则自动打开并等待就绪。
3. 若容器已经健康，直接打开网页。
4. 否则先用本机已有镜像恢复；仅当镜像缺失或启动失败时才执行 Docker Compose build/up，避免每次停机后重复下载依赖。
5. 成功后打开 `http://localhost:8000` 并显示通知；失败时直接弹窗展示最近日志。

项目目录中的 `打开舞蹈老师.command` 和 `start_local.command` 是不依赖原生应用的备用入口。

可通过 `DANCE_TEACHER_PORT` 改宿主机端口。

### 12.2 停止

双击 `stop_local.command` 只执行 Compose stop，不删除容器数据、镜像或 `backend/data`。

### 12.3 容器持久化

- `./backend/data:/app/data` 保存视频、WAV 和任务。
- named volume 保存 numba 编译缓存，后续启动与首次分析更快。
- 容器采用 `restart: unless-stopped`。
- 健康检查允许 numba 首次预热的较长启动期。

## 13. 踩坑与解决方案

| 坑 | 根因 | v1 解决方式 |
|---|---|---|
| 本地 BPM 准、网页不准 | 两个环境使用不同解码/算法链路 | 统一为同一个 Docker 镜像内 ffmpeg + librosa |
| Amapiano/Afrobeats 自动得到 126，但人工 88–89 才能数拍 | 单一 120 BPM 先验被密集的非主拍打击乐吸住；歌曲又存在 178/89 的计数层级歧义 | 增加 180 BPM 候选并用全曲稳定性与 onset 支持裁决；非二倍冲突时自动选择更适合舞蹈 8 拍的半速相位 |
| iPhone MOV 网页 `Decoding failed` | 浏览器/静态站本地音频解码兼容性不稳定 | 服务端 ffmpeg 解码；移动端大文件分块上传 |
| 首次分析卡在 `beat_detecting` | numba 首次 JIT 在 daemon thread 中卡住 | lifespan 主线程预热并持久化 cache |
| BPM 对但第一拍不对 | tempo 与 8 拍相位是不同变量 | 保留手填 BPM、手动第一拍与整数拍偏移；确认后统一重分段 |
| 调整偏移后第一节从 4 秒开始 | 只保留完整 8 拍，裁掉前导残片 | 显式创建前导残缺小节并从 0 秒开始 |
| 末尾最后一节消失 | 聚合逻辑丢弃不足 8 拍尾段 | 尾段仍输出并延伸到 duration |
| 末尾生成零时长小节 | 固定网格把 duration 上的拍点当新起点 | duration 上的拍点只作边界并过滤 |
| 循环 5/11 却跳到 3/11 | 前导拍时按当前播放位置重选目标 | 循环上升沿和显式点击锁定目标，前导阶段不换目标 |
| 循环到边界后偶尔失效 | rAF、seeked 与 React 状态存在竞态 | ref 保存强制目标，程序 seek guard，下一帧优先消费 |
| 多节循环只循环两拍/跳错块 | 数字选择、连续块和游标未统一 | 排序去重、连续段归并、块游标重建并按位置锚定 |
| AB 被单节引擎覆盖 | 多套循环条件同时生效 | AB 分支隔离且优先级最高 |
| 当前三拍循环重复一次后换动作 | 自动回跳的 `seeked` 被当成用户拖动 | 独立保存动作锚点；程序 seek guard 禁止重新锁拍 |
| 前节/后节切换时串到相邻节 | 播放头恰好位于借来的上下文拍 | 切换精细模式时保留显式小节目标，只在缺少目标时按播放头重取 |
| 录制对照视频后老师不再循环 | 对照模式曾把主循环引擎设为 inactive | 对照复用同一老师视频并保持循环引擎 active，六档统一回归 |
| 练习看到拍数，下载对照视频却没有 | 主播放器的拍数是 DOM 叠加层，`canvas.captureStream()` 只录 Canvas 像素 | 每帧在同一录制 Canvas 左上角重绘 1–8 与拍点 |
| 练习时听到口令，录像里没有 | `speechSynthesis` 不提供可录制的 MediaStream 音轨 | 改用本地 1–8 WAV，同一 Web Audio source 同时连扬声器和录制总线 |
| 老师原声和口令各加一条音轨时部分浏览器只播一条 | WebM/MediaRecorder 对多音轨回放支持不一致 | 先经 `MediaStreamAudioDestinationNode` 混成单音轨再录制 |
| 调大口令后现场和下载视频音量不一致 | 扬声器与录像分别维护音量会形成两套状态 | 口令在分流前只经过一个共享 `GainNode`，同一增益同时进入两条通路 |
| 双击也触发单击暂停 | 浏览器会先发 click 再发 dblclick | 220 ms 单击消歧；双击取消 pending click |
| 镜像后双击方向反了 | 按视觉变换推断交互方向 | 手势固定按容器几何，不读取镜像状态 |
| 点击拍点也播放/暂停 | 叠加层事件冒泡到视频 | 控件与圆点显式 stopPropagation |
| 测试把真实课程删了 | 后端测试共享 `backend/data` 并自动清理 | `DANCE_TEACHER_DATA_DIR` 可覆盖；pytest 每次使用 TemporaryDirectory |
| 切换课程带入旧循环状态 | Zustand 是页面间共享单例 | 新课程载入前 reset，再恢复该课程持久化状态 |
| 直接刷新 lesson 路由 404 | 服务器只提供静态文件，不做 SPA fallback | FastAPI 对非 API、非真实文件路径返回 index.html |
| 双击 App 后仍看到旧界面 | 健康容器被无条件复用，浏览器又可能保留旧 SPA 外壳 | 启动器比较运行/目标版本，不一致自动重建；入口 HTML 禁止缓存并用版本参数打开 |
| 回看镜像后播放按钮、时间轴和菜单也反了 | 原生控件绘制在被 `scaleX(-1)` 的 `<video>` 元素内部 | 保留画面镜像，在 Chromium/Safari 原生控件面板上施加一次反向变换抵消父级镜像 |

## 14. v1 已知限制与后续方向

以下内容没有伪装成已完成：

- 自动检测编舞第一拍/downbeat 不是 100%；当前使用人工相位确认闭环。
- URL 上传只保证直接媒体链接；需要在公网投产前补 SSRF、DNS/IP、重定向和流式大小防护。
- 没有账号、云端同步、多人共享和跨设备学习进度。
- 没有姿态识别、动作打分、AI 纠错和逐帧骨架比较。
- 没有自动识别并跳过前奏/间奏，也没有社区分享、官方课程库或原生移动 App。
- 没有手工拖动每一个小节边界；v1 以统一节拍网格为准。
- MediaRecorder、摄像头、Web Audio 和全屏的细节受浏览器/移动系统限制。
- 首次 Docker 构建和首次 numba 预热需要数分钟；之后使用缓存。
- `npm audit --omit=dev` 在冻结日报告 React Router 的 2 个 moderate 公告；v1 仅使用固定内部路由、没有 SSR hydration 或用户控制的跳转目标，当前代码未使用公告中的主要攻击路径。升级到 Router 7 属于需完整回归的大版本变更，留待后续版本。
- v1 冻结的是本地 Docker 完整版；公网免费部署不在本次发布范围。静态 GitHub Pages 无法独立承载 Python/ffmpeg/librosa 后端。

推荐后续版本优先级：

1. 增加“把当前拍设为 1”快捷校准，并探索 downbeat/phrase 模型。
2. 增加可视化小节边界微调，但仍由单一网格派生所有循环。
3. 完成 URL 下载安全加固后，再选择可免费/低成本休眠的容器托管。

- [ ] “前节”循环上一节第 8 拍至本节第 5 拍；“后节”循环本节第 4 拍至下一节第 1 拍。
- [ ] 左栏在前节、后节、单节模式显示与实际引擎一致的秒数范围。
- [ ] 点任意单节后循环目标保持该节，含前一节第 8 拍和后一节第 1 拍。
- [ ] 多节连续选择整体循环；非连续选择按块轮转。
- [ ] AB 吸附真实拍点，A≥B 时不能开启。
- [ ] 单击、三区双击、键盘和全屏互不误触，镜像不改变手势方向。
- [ ] 播放器聚焦时，`,` 前一拍、`.` 后一拍；中英文输入法均按物理键位生效，可编辑控件不触发。
- [ ] 偏移确认后数拍、列表和六档循环读取同一新网格。
- [ ] 开头第一残缺小节和结尾最后残缺小节都能稳定循环。
- [ ] 对照录制时老师视频继续执行用户选定的六档循环。

- [ ] 课程刷新后恢复设置；切换课程不串状态。
- [ ] 测试使用临时数据目录，不碰真实 `backend/data`。
- [ ] Docker 构建、健康检查和 SPA deep link 通过。
